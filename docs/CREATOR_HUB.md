# Idea2Music Creator Hub — pilot implementation contract

Status: isolated development branch, not enabled and not deployed. No production database changes. This first increment is an additive data model, pricing/eligibility rules and unit-test source. It does not yet accept partner orders or provide logins, a portal or automatic payouts.

## Agreed commercial proposal
- Regular €15 including VAT; partner customer pays €13.50, only after introduction offer ends on 1 December 2026.
- €2 commission, €3 after 20 qualifying sales and explicit administrator promotion (prospective only; prior orders retain their snapshots).
- No discount stacking; free introductory song is not commissionable. Monthly payout from €20 net commission; manual bank transfer and documented invoice or appropriate alternative for a non-business partner.
- Proposed implementation decision: 14-day hold after recorded delivery, then explicit review of payment, refunds, chargebacks and self-referrals. This is an accounting control, not a change to consumer rights.
- Pilot partner terms and privacy wording require approval before onboarding. No automatic messages to influencers.

## Next implementation increments
1. D1 migration in separate preview DB. Validate all existing migrations, schema constraints and backup/rollback strategy. Add admin authentication (server-side sessions or Cloudflare Access with verified JWT issuer/audience), partner authentication with secure short-lived one-time links, session cookies, CSRF and rate limiting. No identity or role from client input. Store secrets only in Cloudflare runtime.
2. Add feature flag CREATOR_ENABLED default false. Public quote endpoint looks up active code and partner server-side, never exposes partner email/id or commission. Checkout computes price independently, persists order and immutable attribution atomically via D1 batch, binds retry identity to answers and code, validates exact Mollie payment amount/mode/ID, and preserves regular checkout, invoice and email flows. Use /bestellen.html?ref=CODE; allow manual code entry and removal before checkout. Add attribution only when valid and customer accepts quoted total. No cookie required for link-based attribution.
3. On verified payment, insert one pending commission per order/payment id (idempotent). Do not use incoming webhook fields as proof. Record delivery via authenticated admin action, require verified fresh refund/chargeback status before release and payout, handle cancellations and same-account referrals. Add explicit status transitions and append-only adjustment for refunds after payout; repeated provider events must not duplicate adjustment. Make code and attribution consistent with partner, check totals in transactional server code. Existing orders stay unchanged.
4. Public partner landing and real application form. Private creator portal shows own aggregate and commission rows without customer identities, stories or payment tokens. Admin can manage approvals, terms version, codes, delivery, commission review and payouts. Add audit records without PII payloads, scoped authorization on every route, privacy notice and retention policy. No public admin data or secrets.
5. Payout: atomically reserve eligible rows, prevent duplicate inclusion, verify partner ownership and totals, apply adjustments and hold unresolved cases. Prepare monthly statement; verify tax status/documentation, transfer manually via bunq, record bank reference and mark paid only after confirmation. Export to e-Boekhouden workflow. Define void/retry and reversal accounting before activation.
6. Test with fake providers and separate preview DB; no live keys, real orders, emails, or payments in automated tests. Regression tests: unchanged normal checkout, intro discount, invalid/disabled codes, price tampering, parallel duplicate checkout, webhook retries, refund/chargeback after payout, ownership/authorization, session expiry, no leakage, payout threshold, duplicate payout and invoice totals. Validate preview before production release. Production migration and feature activation require explicit approval.

## Existing architecture
Static HTML and JS, Cloudflare Pages Functions, D1 ORDERS_DB, Mollie and e-Boekhouden. Existing checkout priceAt and syncPayment remain unchanged in this first increment. Do not modify main or live runtime configuration. Execute npm test in Node 24+; tests in this commit are source until their execution is confirmed.
